# Glossary

This file defines shared terms used by design documents and future implementation.

| Term | Meaning |
| --- | --- |
| Ambition | A self-chosen player goal prompted by something visible or known in the world. |
| Base item | The physical item produced from material and form before advanced properties are applied. |
| Build | The persistent combination of skills, supports, passive choices, equipment and properties. |
| Build palette | The construction interface for selecting shapes available to the current material family. |
| Capability | Something the player can now do that was previously impossible or impractical. |
| Catalyst | A rare crafting input used during a production step to influence or preserve item properties. |
| Class hall | An authored world location tied to the starting class that opens a vertical specialisation path. |
| Craft skill | Use-developed competence such as blacksmithing that gates more complicated work. |
| Facility | A station, tool, machine or powered process required to perform a craft operation. |
| Material family | A stored resource such as oak or granite that can be formed into unlocked construction shapes. |
| Modifier | A property attached to equipment that changes statistics or mechanics. |
| Outpost | A small functional base near a resource, route or trial. |
| Persistent progression | Character, settlement, knowledge and equipment state retained between trials. |
| Productive friction | Repetition or scarcity whose output serves a meaningful world, trade or construction purpose. |
| Trial | A repeatable combat challenge; it may be a temple, tower, forest, mine or other structure rather than a literal dungeon. |
| Trial boon | A temporary beneficial rule selected or discovered during the current trial attempt. |
| Trial weakness | A temporary disadvantage, curse or trade-off active during the current attempt. |
| Vertical slice | The smallest playable implementation containing one complete representative return loop. |

Add new terms when they prevent ambiguity across two or more specifications. Do not use the glossary as a substitute for system rules.
